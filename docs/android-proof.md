# Android 独立运行验证版

> 本文保留早期一页验证版的实施与真机记录。当前采集与报告版的功能、安装包及验证边界见 [Android 内容采集与报告](android.md)。现在运行 `npm run android:apk` 生成 `DouyinDataReview-Android-arm64.apk`。

目标：在手机内登录抖音，读取第一页面（最多 20 条）观看历史，保存到手机，关闭应用后仍可离线查看。

## 使用

1. 安装 `release/DouyinDataReview-Android-proof-arm64.apk`，打开 DouyinDataReview。
2. 点「登录并读取一页」，在应用内的抖音网页完成登录或身份验证。登录操作由本人完成。
   如果出现「使用原设备扫码」的身份验证二维码，先确认极速版当前账号与网页登录账号一致，再点顶部「在本机极速版验证」。在官方页面由本人确认，再手动切回本应用。此入口目前仅适配极速版，二维码过期需先在官网刷新。平台如提出其他验证要求，仍须按官方页面完成。
3. 等待个人主页的「观看历史」列表出现，再点顶部「读取并保存一页」。如登录后停在其他页面，点顶部「打开我的观看历史」。网页可以双指放大。
4. 成功后显示账号、条数、保存时间和作品列表。关闭应用、断开网络并重新打开，检查相同记录是否恢复。

本版只读取观看历史的一页，不表示已导出完整历史。平台未提供的观看时间显示为「平台未提供」，不使用作品发布时间替代。空页、登录失效、限流、超时和账号变化分别处理，失败不覆盖上一份有效记录。再次成功读取会替换当前页。

首次登录是否要求扫码由抖音决定。2026-10-26 真机中，极速版从相册识别验证二维码被拒绝，短信登录也触发验证，当时通过另一块屏幕扫码完成。2026-10-27 使用独立应用数据空间分别实测了直接登录，以及出现「使用原设备扫码」后跳转本机极速版的完整流程；两条路径均由本人完成登录，实际读取并保存了 20 条观看历史，无需另一块屏幕。

新增入口使用系统 WebView 的 `BarcodeDetector` 读取网页中当前的身份验证二维码，把原有官方链接交给本机极速版。不需要截图、相册识别、相机权限或电脑服务。已验证有效二维码进入极速版官方身份确认页，用户本人同意后回到测试包完成登录；过期二维码显示官方「该二维码过期」。无法识别、不支持的二维码或缺少极速版时显示原因，不更改二维码的验证参数，也不自动确认身份。

## 构建

使用仓库当前 Expo / React Native 版本。需要 Node.js、JDK 17、Android SDK，以及构建提示要求的 SDK/NDK。当前依赖需要 Android API 36、Build Tools 35.0.0 和 36.0.0、NDK 27.1.12297006、CMake 3.22.1。

```sh
npm ci
npm run android:apk
```

脚本优先使用 `JAVA_HOME` / `ANDROID_HOME`，在 macOS 上也会探测标准 Android SDK 和 Homebrew JDK 17 路径。生成的 `android/` 是可重建目录，不纳入 Git。仅生成工程可运行 `npm run android:prebuild`。

构建限制为一个 Gradle 工作进程、两个 C++ 编译任务和两个 JavaScript 打包任务，以控制内存占用。

APK 内嵌 JavaScript，启动不依赖 Metro、电脑采集器或局域网。当前 APK 仅包含 ARM64，使用 Expo 模板的开发签名，供本次验证；尚未建立正式发布签名和升级渠道。

验证版启用 WebView 调试，便于通过本人授权的 USB 调试检查登录和读取失败的原因。正式发布前应关闭此调试入口。

## 实现边界与验证

- 安卓通过 `App.android.tsx` 进入专用验证界面；原 `App.tsx` 继续用于桌面/Web。
- 读取在本机 Android WebView 中执行，复用当前抖音网页的登录会话和请求 SDK。按用户点击发送账号确认、第一页历史、再次账号确认三个只读请求。没有后台翻页或自动重试。
- 请求模板来自个人主页实际发出的观看历史请求；未观察到模板时提示先打开历史列表，不编造参数。验证码及平台限制由官方网页处理。
- 允许平台 SDK 将只读请求调度到 `www.douyin.com` 或 `www-hj.douyin.com`，并校验 HTTPS、端口和响应路径；其他响应地址不作为有效采集结果。
- Cookie 留在应用的 WebView 私有存储中，不传给 React Native、不写入记录文件。原始接口响应和带凭据的读取请求 URL 不落盘。仅在本人点击验证入口时，当前二维码中的短期验证链接在内存中经过原生层转交极速版，不打印、不持久化、不改写原有参数。
- 验证链接限定到实际观察到的 HTTPS `api.amemv.com` 身份验证页面，并校验请求编号、消息来源及必要参数；通过明确包名和 Activity 打开极速版，避免把短期链接交给其他应用。打开 Activity 成功不等于登录成功，最终仍以官网登录和读取结果为准。
- 记录以两个交替写入、回读校验的文件保存在应用私有目录 `android-proof/page-0.json` 与 `page-1.json`。只保留当前和上一份有效快照，写入中断时恢复上一份。禁止 Android 自动备份。
- `src/mobile/proof.test.ts` 与 `verification.test.ts` 使用明确的合成数据验证读取、保存恢复、二维码识别、消息来源与编号校验、链接限制、固定跳转目标和失败处理。运行：`npx vitest run src/mobile/proof.test.ts src/mobile/verification.test.ts`。
- 自动测试、JavaScript 打包、APK 编译、模拟器启动与本人账号真机登录采集是不同的验证层次。真实登录和接口兼容性必须在手机上完成验证，不能由合成测试替代。
