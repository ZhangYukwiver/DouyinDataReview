# 群聊白名单存储

群聊正文按账号配置保存白名单。默认白名单为空，群名和消息统计继续保存。

## 使用

1. 登录账号并开始接收聊天，让群列表完成读取。
2. 在「设置 → 隐私 → 保存群聊消息」勾选需要保存的群。
3. 白名单以群会话 ID 识别，群改名不影响设置。勾选后会直接保存已经读取的群消息，接收连接及暂停状态保持原样；正在接收时，仅为新加入的群补读缺少的历史，复用已读取页面及游标。
4. 聊天页优先显示已保存的群消息，展示最近 320 条，并提示仍保留在本地快照中的更早消息数量。连接可用时可点击「从抖音补读历史」，补读结果与当前显示的本地内容合并。
5. MCP 先使用 `list_conversations` 查找群：`group` 标识群聊，`storageEnabled` 表示当前是否在保存白名单，`localMessageCount` 是本地正文数量。仅当群在白名单且本地有消息时选择 `read_chat`，其他情况一律选择 `read_live_chat`。三个工具的描述使用同一条选择规则；`messages` 仍表示采集统计数量。

群聊右上角按保存开关显示：开启为「本地保存」，关闭为「不存本机」。从抖音实时读取时，副标题说明当前读取方式。

关闭保存时会弹出与账号删除相同的确认框，说明群名和本地消息数量。取消则保留开关及记录；确认后删除该群已保存的本地正文，并停止保存新消息。群名和采集统计保留，抖音上的消息不受影响。重新开启后，需要重新读取历史。

## 数据与导出

- 白名单保存在各抖音账号的数据目录下的 `group-chat-storage.json`，不同账号互不共用。
- 已授权正文随其他记录保存在 `records.json`，按消息 ID 去重。沿用上游的 10 万条聊天消息和约 480 MB 快照限制，超出消息条数时保留最新消息。
- `export_chat` 可以导出当前白名单内指定群；全量聊天导出同样过滤未在当前白名单中的群正文。
- 导入文件中的白名单元数据不会授予采集器授权。目标账号需要自己配置白名单，才会导入相应群正文。
- 关闭保存会清理本地快照和接收缓存，聊天页立即更新，即使当前已暂停接收也无需重新启动。删除失败时恢复原设置。账号切换期间禁止修改白名单，写入时还会核对设置所绑定的账号。

历史读取沿用上游分页和页数上限，保存的是接口实际返回的消息，不保证可以取得全部历史。群语音沿用原有格式，尚未支持的转写会注明原因。

## 开发与验证

```bash
npm ci
npm run typecheck
npm test
npm run build:web
```

专门覆盖白名单、重启、移除、账号隔离、历史与实时接收、MCP 本地读取和导出的测试位于 `collector/groupChatStorage.test.mjs`。

界面回归检查使用 400 条合成群消息，验证本地视图展示最近 320 条并提示更早消息数量、完整历史仍保存在本地、打开本地群时不请求远程，以及显式补读后仍保留本地内容。构建完成后运行：

```bash
# 使用已安装的 Playwright 浏览器
node scripts/check-group-chat-ui.mjs
# macOS 也可以指定已安装的 Chrome
DY2_CHROMIUM="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" node scripts/check-group-chat-ui.mjs
```

检查使用随机本机端口和独立临时数据目录，不登录真实账号，完成后关闭服务并清理合成数据。还会验证“已有群消息 → 勾选白名单 → 消息保持展示”、取消删除、删除失败、确认删除后清理本地正文及暂停接收时的界面更新。
